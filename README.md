## Исправление приёма SMS — v0.6.0

Если бот отвечал, но история SMS оставалась пустой, в v0.5 были два пути пропуска сообщений:
* флаг `enabled` записывался только при запуске через экран приложения; выдача разрешения в настройках Android позже не обновляла его;
* исключение при определении слота или привязанного номера SIM отменяло сохранение всего SMS.

В v0.6 разрешение RECEIVE_SMS проверяется в момент работы. Явная остановка бота по-прежнему останавливает приём и отправку. Ошибка сведений о SIM не блокирует сохранение текста: при необходимости указывается неизвестный номер. Уже принятая очередь отправляется при работающем боте независимо от разрешения на приём следующих SMS.

Главный экран, история и `/status` показывают разрешение, время последнего SMS_RECEIVED, последнее сохранение и причину пропуска/ошибки. Диагностика не выводит тело SMS, токен или тексты исключений. Успешный ответ Telegram не стирает ошибку приёма.

При новом принятом SMS приёмник теперь также запрашивает запуск постоянного сервиса. Если Android отклоняет запуск, SMS остаётся в очереди, а причина видна в `/status`. Уже назначенная периодическая задача не пересоздаётся при каждом SMS, поэтому её окно не сдвигается заново. Отказ планировщика больше не мешает отдельной попытке запуска сервиса. Диагностика показывает последнее выполнение сервиса и резервной отправки. Ошибка `startForeground` внутри асинхронного `onCreate` также фиксируется: `try/catch` в BootReceiver сам по себе её не перехватывает.

Периодическая задача только отправляет очередь; она не заменяет постоянный Telegram polling и не гарантирует задержку до 15 минут. Ограничения автозапуска Xiaomi необходимо разрешить в системных настройках, режим батареи для приложения — «Без ограничений». Программа сама эти переключатели не меняет. На постоянно подключённом к питанию телефоне обычный Android Doze обычно не действует; ограничения производителя — отдельный механизм. См. [документацию Android](https://developer.android.com/training/monitoring-device-state/doze-standby) и [правила автозапуска Xiaomi](https://dev.mi.com/xiaomihyperos/documentation/detail?pId=1624).

Это исправление найденных дефектов, а не подтверждение точной причины на конкретном Xiaomi. Если событие SMS_RECEIVED не доставлено системой, диагностика покажет отсутствие события; приложение не читает старый SMS-ящик. Новые звонки и объединённое управление eSIM в эту сборку не включены.

# SMS Мост — 0.3

Личный Android SMS relay для выделенного телефона дома. Пользовательское приложение
и интерфейс Telegram написаны на русском. Первый APK собран через GitHub Actions;
компиляция и lint прошли. Работа на Xiaomi и удалённая установка eSIM ещё не проверены.
Сначала прочитайте [START-HERE.txt](START-HERE.txt).

## Быстрый запуск v0.2

На Android: токен + Telegram ID получателей через запятую → «Запустить бота». В своём Telegram
получатель пишет /start. Владельцу Android не нужно подключать свой Telegram.
Если ID неизвестен, остаётся альтернативное подключение по восьмизначному коду.
Бот запускается до подключения получателя и отвечает независимо от разрешения SMS.
Загрузка APK сама по себе не может запустить бота без его токена и первоначального
открытия приложения/разрешений Android.

После временной debug-подписи первой версии используется постоянный личный ключ,
поэтому старое приложение надо удалить перед установкой v0.2. При удалении теряются
локальные настройки и очередь; новые версии можно подписывать тем же личным ключом.


## Сборка приложения

JDK 17, Gradle 8.11.1, Android SDK 35 / build-tools 35.0.0.
AGP 8.9.2, Java 17, minSdk 28, targetSdk 35. Единственная внешняя библиотека приложения
— ZXing Core 3.5.3 для чтения изображения QR. Gradle wrapper отсутствует;
используйте установленный Gradle или предоставленный GitHub Actions workflow.

```sh

gradle :app:assembleDebug :app:lintDebug :app:testDebugUnitTest
```

В Android Studio: импорт проекта, установите SDK 35, затем выберите сборку APK.
Не публикуйте debug APK в Play Store. Код получения SMS не делает приложение SMS-handler
по умолчанию и не читает старую историю SMS телефона.

## Привязка номера к eSIM

Номер обязателен, вводится пользователем ДО QR-кода. После ответа загрузчика сохраняется
таблица `EID:ICCID → введённый номер`. Активация вызывает перепроверку профилей; подпись
каждого полученного SMS сохраняется в очереди и не пересчитывается перед отправкой.
Если ответ загрузки потерян, intended number/code остаются в зашифрованном `last_install`,
профиль не сопоставляется автоматически по догадке; его можно выбрать и задать номер
в меню профилей. QR-код не повторяется автоматически, поскольку он может быть одноразовым.

Пользовательская подпись не является проверкой права владения номером и не изменяет
данные профиля оператора. Следует вводить номер именно предоставленного оператором профиля.

## LPA companion — экспериментальная интеграция

Контракт реализован для open source `Laiteux/openeuicc-bridge`:
https://github.com/Laiteux/openeuicc-bridge

Адаптеру нужен подписанный и разрешённый LPA. Обычный APK SMS Мост не обладает допуском
к карте. В комплект входит сборщик companion, использующий исходники bridge и его LPA APK;
этот путь не был собран в данной среде. Не устанавливайте исходный bridge с открытым
`content://lpa`: сборщик удаляет его открытый provider и регистрирует защищённый
`ru.smsbridge.lpa`. Gateway допускает только package `ru.smsbridge.app` с SHA256
сертификата конкретного relay APK. Публичный Community Key используется только для
допуска LPA к адаптеру; он НЕ служит ключом доверия к управляющему приложению.

В обратном направлении `LpaClient` проверяет закреплённый SHA256 сертификата companion.
Неизвестный provider, неподтверждённая подпись или сборка без pin → отказ, а не утечка QR.
Gateway запрещает удаление профилей, произвольные callback URL и отключение TLS.

Производитель публикует ключ:
https://github.com/9esim/9eSIMCommunityKey

В описании ключа указана V2, поэтому право доступа этим ключом к **V0 ещё требует теста**.
Сборщик не обходит правила авторизации карты. Успешная сборка APK не доказывает наличие
доступа на V0. Если доступа нет, нужен разрешённый производителем LPA/интерфейс.

### Сборка двух согласованных APK

Скачайте и проверьте checkout bridge; выберите конкретный commit, не непроверенный latest.
Потребуются apktool, Python 3, javac/JDK, Android build tools и JAR-зависимости из bridge.

```sh
python3 tools/prepare_signer.py
gradle :app:assembleDebug :app:lintDebug :app:testDebugUnitTest -PlpaSignerSha256="$(cat vendor/community/sha256.txt)"
mkdir -p dist
cp app/build/outputs/apk/debug/app-debug.apk dist/SMS-Most.apk
python3 tools/build_companion.py --bridge /absolute/path/to/reviewed/openeuicc-bridge --relay-apk dist/SMS-Most.apk
```

Установить нужно оба APK. Перед первым использованием открыть LPA-компонент на телефоне,
проверить доступ к карточке, затем включить управление 9eSIM в SMS Мост. Совместимость
вызовов delegate, schema ответа и разрешённого сертификата проверяется на реальной карте.
Сборка завершится ошибкой при несовместимых исходниках/зависимостях; никакого фиктивного
«eSIM установлена» в клиенте нет. В CI adapter отключён по умолчанию до выбора проверенного
commit и доступности карты, но клиентская функция eSIM включена в исходники сейчас.

## Защита и эксплуатация

AndroidKeyStore AES-256-GCM: токен, черновики QR/номер и payload очереди шифруются.
Backup отключён. Доступ бота — один привязанный private chat, совпадение user ID и chat ID;
явный Telegram ID или одноразовый код на 30 минут; nonce/срок в подтверждениях операций. При изменении Telegram-чата
нужно остановить пересылку и завершить либо явно удалить прежнюю очередь. SMS не перенаправляются
новому чату задним числом. Постоянный foreground service с уведомлением и кнопкой остановки.
Только HTTPS; TLS verification не отключается. Коды активации не пишутся в логи.

Пропавшая сеть → очередь + экспоненциальная задержка, Telegram 429 → retry_after. Части
длинного SMS учитываются отдельно. Идентификатор сообщения помогает различать неизбежные
дубликаты при сетевой неопределённости. Входящий системный broadcast защищён BROADCAST_SMS;
старые SMS не читаются. Во время неопределённого состояния адаптера номер не выдумывается.

## Проверка на Xiaomi 12T / V0

1. Собрать APK и пройти Android Lint; проверить установку на конкретной MIUI/HyperOS.
2. Привязать Telegram, выдать разрешения, разрешить автозапуск и работу без ограничений батареи.
3. Проверить обычную физическую SIM: номер, sender, кириллица, multipart SMS.
4. Выключить Wi-Fi, получить два SMS, включить Wi-Fi: очередь должна уйти в исходном порядке.
5. Заблокировать экран на час, проверить доставку; затем перезагрузка + первое разблокирование.
6. Установить защищённый LPA, проверить доступ V0. Без этого удалённое eSIM provisioning не подтверждено.
7. Добавить eSIM, введя номер A. Проверить EID/ICCID, активацию и реальное SMS на A.
8. Добавить второй профиль с номером B; переключить, убедиться, что новые SMS имеют подпись B,
   а старая очередь сохраняет A. Проверить неизвестный номер при неподтверждённом переключении.
9. Повторно нажать подтверждение установки: оно не должно снова расходовать QR-код.
10. Попробовать чужой Telegram-chat и стороннее Android-приложение: управления и доступа к QR нет.

## Статус проверки

Локально доступны только JDK и Python: pure Java tests, Java syntax parse, Python syntax и XML.
Android-компиляция и lint выполнены в GitHub Actions; проверены подпись и целостность APK.
UI на устройстве, Telegram API с реальным ботом и 9eSIM V0 не проверены.
В исходники не включены токены, номера пользователя, ключи, APK сторонних разработчиков
или ложные результаты аппаратных тестов.

## SIM-карты без 9eSIM (v0.3)
«Мои SIM-карты» в приложении и /profiles в Telegram читают активные SIM
непосредственно из Android. Разрешение «Телефон» выдаётся один раз на Android.
Номер можно вручную задать для каждой SIM в приложении или боте. Компонент
9eSIM для этого не нужен. Управление профилями адаптера вынесено в отдельный
дополнительный раздел и выключено по умолчанию. При выключенном управлении
SMS используют номер обычной SIM, а не устаревшие данные адаптера.
Обновление с доставленного v0.2 устанавливается поверх него, с сохранением настроек.
